# 楼响 HouSignal 产品 PRD

版本 v0.1，2026年10月11日。面向创始人、产品设计、技术合伙人、内容运营和销售负责人。状态：开发与试点方案，尚未实现或完成业务验证。首个服务对象已确认是豪宅销售团队；抖音主渠道、小红书图文适配和六周研发周期是可调整的首轮建议。

## 1 产品目标与核心决策

楼响把一线房产经验转成能够重复使用的事实资料、内容方法和销售反馈。首轮交付一个销售团队、一个真实楼盘、一条内容生产链路、一个合规咨询入口及一套轻 CRM。团队能从资料生成并审核真实内容，人工发布后记录平台结果，接住主动咨询，并根据销售反馈提出下一轮选题。

产品定位语：房产内容获客 AI。对客户的价值表达：把好房讲清楚，把主动咨询接住。传播文案可以表达愿景，销售合同和产品界面不能承诺必然获客或成交。

北极星指标采用“每个客户每30天新增、经销售确认的去重资格线索数”，同时展示当期投入和来源不明比例。上线初期没有合理业务基线，先建立两周原流程基线，再评价四周试点。内容产量是过程指标，不能代替获客结果。

## 2 从小艾大叔内容研究得到的设计原则

公开作者资料呈现出按真实空间动线组织讲解、通过居住体验表达价值、用具体差异制造选题兴趣的方向；有些公开标题也表达不认同和取舍。这些观察支持产品设计，但不能推导其私人制作流程、销售方式或获客效果。样本和证据级别见[内容研究](01_小艾大叔内容研究与产品启发.md)。

| 方法启发 | 产品机制 | 首轮验证方式 |
| --- | --- | --- |
| 空间按生活动线讲清楚 | 镜头按到达、会客、厨餐、起居、私密、服务组织 | 事实负责人能逐镜头核对位置与用途 |
| 豪宅价值需要具体解释 | 每个卖点至少有一个可核查事实或具体场景 | 不接受仅由高级、奢华等形容词组成的脚本 |
| 面积和价格不能代表适合程度 | 每个选题写目标客群、使用需求和取舍 | 销售能指出适合与不适合的需求 |
| 专业判断可以表达边界 | 主观判断标明“顾问观点”，与事实分离 | 不把偏好写成普遍事实或投资结论 |
| 观看兴趣与购买需求不同 | 观看、咨询、资格线索、带看分开记录 | 系统不能把播放量或点赞换算成客户 |
| 创作者有自身判断 | 品牌档案来自客户授权表达 | 不复制小艾大叔身份、声音、固定口头禅 |

核心内容结构为“问题或差异 → 可证实细节 → 生活中的意义 → 取舍与适合人群 → 一次合规咨询邀请”。这是产品设计方法，不是对某个创作者原文的复刻。

## 3 用户角色与真实任务

| 角色 | 主要任务 | 当前痛点假设 | 可见与可操作范围 |
| --- | --- | --- | --- |
| 客户管理员兼销售负责人 | 安排楼盘、分工、预算、销售跟进 | 内容投入看不到销售反馈 | 本客户全部业务；授权、分配和报表 |
| 楼盘事实负责人 | 核验房源、报价、产权描述、交付与配套 | 文案版本与最新资料脱节 | 事实库批准和撤回；无需查看手机号 |
| 内容运营 | 选题、脚本、素材组织、包装、发布 | 资料散乱、返工多、多平台重复改稿 | 内容与匿名反馈；联系方式默认不可见 |
| 内容审核人 | 审核镜头、主张、标识和咨询邀请 | 缺少可追踪的审批对象 | 审批指定内容版本与发布快照 |
| 销售人员 | 回应咨询、确认需求、预约、带看、反馈 | 不知道客户从哪条内容来及为何有兴趣 | 本人负责的联系人和 CRM，其他联系人不可见 |
| 平台支持管理员 | 诊断系统问题 | 排错可能接触隐私 | 默认只有脱敏运行信息，受控临时访问 |

首轮角色可由2至4人兼任；责任逻辑保持独立。公网咨询者只接触入口和确认页，不可读楼盘内部资料、运营指标或其他客户数据。

## 4 用户故事与成功场景

运营希望将一次授权拍摄与一次销售访谈，整理成可反复使用的房源资料；不再每写一条内容都重新问销售。事实负责人希望看到每句数字或房源描述的证据、适用房源和有效日期，防止过期报价再次发布。

运营选择“有长辈同住的家庭为什么需要关注日常动线”这一选题，系统只调用已核验资料，生成脚本、缺镜头清单和分镜。真实素材不足时显示待补拍。运营完成剪辑预览，审核人对具体版本批准，导出发布包。发布后录入平台 URL 或作品 ID，并在固定窗口登记后台指标。

咨询者在平台允许的入口主动咨询。销售在取得相应联系和记录授权后，将咨询录入 CRM。系统显示来源可信度，销售确认客户是否有真实置业或看房需求，并记录关键疑问。复盘可以提出“下一条补充楼层动线说明”，但只有运营批准后才成为任务。

示例只描述预期行为；真正试点必须使用客户拥有营销许可的真实楼盘和真实授权素材。

## 5 产品边界与功能优先级

P0 是首轮闭环必须完成的功能，P1 是试点后条件满足再做的增强，P2 是长期候选。平台未授予的能力不因标记 P0 而自动可用。

| 模块 | P0 首轮交付 | P1 增强 | P2 候选 |
| --- | --- | --- | --- |
| 组织与权限 | 客户隔离、角色、审计、负责销售 | 多楼盘、多内容团队 | 企业组织与审批层级 |
| 楼盘事实 | 结构化事实、证据、核验、有效期、适用房源 | 客户授权资料系统同步 | 多源冲突辅助分析 |
| 素材 | 真实图像、视频、录音、文档上传与授权范围 | 更细粒度检索和直播片段索引 | 复杂多模态素材管理 |
| 选题 | 客群、任务、事实依据、缺口、人工选择 | 用户授权历史表现排序 | 大范围市场洞察，需合规来源 |
| 文案 | 口播、分镜、封面标题、字幕、图文 | 长视频和多角色口播 | 多语言与完整节目 |
| 视觉 | 真实素材编排、基础剪辑、字幕和封面 | 更多剪辑模板、明确标识的创意图 | 高阶视觉生成 |
| 渠道 | 抖音主包、小红书图文包、人工发布记录 | 经批准的官方发布能力 | 条件允许的多平台运营 |
| 复盘 | 手录指标与凭据、固定窗口、建议任务 | 正式授权数据接口 | 受控实验与预算建议 |
| 线索 | 一个可用合规入口、人工导入和去重 | 经批准的官方线索组件 | 多入口及正式 CRM 连接器 |
| CRM | 资格确认、负责人、跟进、预约、带看、机会、反馈 | 提醒与客户已有 CRM 同步 | 企业完整客户管理 |
| 音频与直播 | 授权录音转写、真人口播素材、人工直播提纲 | 授权长音频和直播切片 | 其他能力须另立范围 |

首轮不包含自动私信、平台数据抓取、自动投放、未经授权的声音或肖像克隆，也不包含房屋交易、贷款建议和投资预测。

## 6 信息架构与主操作路径

工作台按“待我处理”组织首页：待核验事实、缺素材、待审核、待发布回执、待销售跟进及待反馈。左侧导航为楼盘资料、内容任务、发布记录、咨询与 CRM、复盘、设置。让用户看到下一件需要自己确认的事，避免把模型调用过程塞进业务界面。

```mermaid
flowchart LR
    A[授权资料与素材] --> B[人工核验事实]
    B --> C[选题和客群]
    C --> D[脚本和分镜]
    D --> E[真实素材成片]
    E --> F[审核发布快照]
    F --> G[导出并人工发布]
    G --> H[发布回执与指标]
    H --> I[合规咨询入口]
    I --> J[销售确认与跟进]
    J --> K[复盘建议]
    K --> C
```

页面字段、空态、权限与阻塞行为见[页面交互](04_信息架构与页面交互.md)。

## 7 P0 功能需求与验收条件

### FR01 客户与楼盘建档

管理员创建客户组织和楼盘，填写营销主体、楼盘名称、城市、公开范围、营销许可负责人、在售或可推广的房源版本、渠道账号、事实负责人、内容负责人及销售承接人。具体门牌、业主信息和未公开交易资料默认仅内部可见。确认营销许可与素材可用范围后才能进入对外内容流程。

验收：未填写责任人或许可凭据时可保存草稿，但无法生成可审批的发布快照；其他客户不能通过列表、搜索、文件地址或 API 访问该楼盘。

### FR02 授权素材与录音转写

支持真实图片、视频、音频和 PDF 或文字资料上传。每个素材保存所有者、许可主体、许可证明、可使用渠道、有效期、可否剪辑、可否用于模型处理、可否对外发布和撤回方式。许可未知的素材只能在草稿资料区展示，不进入渲染或发布包。

音视频可生成带时间码的转写草稿。转写中价格、面积、用途和交付信息只是事实候选；OCR、ASR 或模型识别不构成核验。失败的素材单独显示错误并允许重试，不清空其他已完成资料。

验收：未授权素材进入时间线时阻塞；每段转写可回看原素材与时间段；上传任务可取消、断点恢复或明确提示重新上传，系统实际支持方式以技术验收为准。

### FR03 楼盘事实库

事实分为可核查主张、顾问主观判断及示意说明。可核查事实保存 fact_id、property_id、适用房源、字段、值与单位、来源文件和页码或时间码、核验人、核验时间、有效起止日期、对外公开范围和版本。状态为 unverified、verified、disputed、expired。

报价、在售状态、可预约时间、促销、物业费及配套变化须设置有效期；无需硬编码所有事实统一过期天数。售价必须区分挂牌报价、具体房源报价与历史成交，不把来源混用。面积必须注明建筑面积、套内面积或其他口径，不能自动换算。产权、学区、税费、政策、交通时间等内容必须有适用条件和现时依据。

核验人逐条批准；多个资料冲突时进入 disputed，显示两份依据，不能由模型挑较好卖的值。到期变为 expired；相关未发布审批失效，已发布内容进入复核列表。引用尚未核验信息的脚本仍可保存为草稿，但不能通过对外发布审批。

验收：脚本每句事实能点到原证据；过期、冲突或跨房源事实出现在对外主张中时阻塞审批；更新事实产生新版本并保留旧记录。

### FR04 客群与品牌档案

团队选定本轮目标需求，例如家庭改善、长辈同住、独立会客、居家办公。客群是内容假设，不是对真实个人的财富推断。记录需求、主要顾虑、适合条件及不适合条件，不建立高净值人员画像库。

品牌档案包含语气、常用结构、表达偏好、禁止词、公开观点及客户授权的历史样稿。首轮提供“专业顾问”“生活体验”“空间解析”三种表达方向。客户可以编辑，不以“小艾大叔本人风格复刻”作为商品功能。

验收：改变品牌语气不改变事实；没有授权样稿时用通用结构；不能生成声纹或身份冒用素材。

### FR05 选题洞察与计划

输入由已核验事实、授权素材、销售匿名问题和客户授权的历史指标组成。首轮生成5至10个候选题，展示目标客群、要解决的问题、核心事实、所需镜头、可表达的取舍、建议渠道、咨询目的和缺资料项。排序由内部规则与人工判断组成，显示原因，不显示未经校准的“爆款概率”或“成交概率”。

运营选定一个主选题，可改写、取消或延后。缺关键事实或镜头的选题标为“需要补资料”，不能在后台擅自补全。内容计划包含负责人、审批人、预计发布日期和一次咨询邀请。

验收：所有选题都有至少一项真实依据和明确需求；不从未授权平台抓取趋势；销售反馈生成的选题可追到脱敏反馈，不暴露联系人。

### FR06 文案与分镜生成

首轮主片建议60至90秒，生成开场、主体、取舍和结束邀请；时长为编辑目标，以试听和渲染后的实际时长为准。每句有 claim_type 和 fact_refs，分镜记录镜头位置、动作、对应素材、素材入出点、字幕及缺口。系统同时生成封面标题、简介和小红书图文结构。

以事实为基础解释生活意义。例如“房间在同一楼层”属于事实，“减少日常跨层活动”需要具体生活条件或作为顾问判断；“最适合所有三代家庭”不能自动得出。谈优缺点要说明针对哪类需求，不贬损其他房源或虚构缺陷。不得制造投资回报承诺、价格趋势保证、稀缺名额和未经证实的销量。

验收：改写后仍保留事实引用；关键数字无依据时留空或提问；不以免责声明修复虚假事实；人工可对每句编辑，编辑产生新版本。

### FR07 真实素材剪辑与视觉制作

P0 包含镜头时间线、基础裁切、片段拼接、字幕、标题图和封面，从真实授权素材产生一条可播放 MP4。运营可调整素材、裁切区域、字幕和顺序；预览必须显示实际产物，不能用“渲染任务成功”替代成片验证。

建议主片采用9比16、1080乘1920，导出前检查原素材是否支持该比例；横屏素材裁切遮挡关键信息时提示换镜头或采用合适版式，不能为了填满竖屏生成不存在的房屋部分。字幕应避开客户确认的各平台 UI 遮挡区，封面文字可人工校正。输出包括 MP4、封面 JPG 或 PNG、UTF-8 SRT、发布文案和素材清单。

首轮生成式视觉仅允许非房源示意图、信息图和排版，使用位置及标识需审核；不得改变户型、层高、景观、朝向、采光、装修或交付状态。修色不得让普通素材成为虚假的景观或房况。真人录音或客户授权语音可以使用；拟使用通用合成语音时需供应商许可、标识与账号规则核对，不进入首轮必需路径。

验收：至少一条60至90秒真实素材成片能够在浏览器和常用播放器播放，声音、字幕、画面一致；缺素材时停止在缺口列表，不以黑屏、假房源或生成景观充数；渲染失败能从已批准输入恢复，幂等控制避免重复创建任务。供应商结果未知时先核对，实际重渲染费用须显示并受预算限制，不保证重复执行没有额外费用。

### FR08 多平台包装与审核

一个内容母版可产生抖音视频发布包和小红书图文适配包。第二平台包装至少包括标题候选、图文顺序、图片来源、正文、说明和允许的咨询邀请；不承诺同一版本在不同平台获得相同效果。每个渠道保留自己的版本、账号、入口能力和规则核对记录。

审批对象是不可变 release_id，包含事实版本、脚本版本、媒体文件校验值、封面、字幕、渠道文案、账号、标识、咨询入口和许可范围。核验事实、素材授权、标识及 CTA 均通过才可批准。任何实际输出或发布配置变化都使原审批失效，包括修改标题、字幕、价格、入口和账号。规则资料的更新时间与适用账号要可见。

验收：新版本需重新批准；审批人可看到所有实际输出；系统能解释阻塞原因和责任人；审批记录不能被编辑覆盖。

### FR09 导出与真实发布记录

运营下载批准的包，在平台官方界面人工发布，随后登记 publication_id、对应 release_id、平台、账号、作品 URL 或作品 ID、发布时间、登记人和凭据。导出状态与发布状态分开；没有回执的任务显示“已导出，待确认发布”。回执核对状态 status=recorded/verified/removed/inconsistent，平台实际状态 platform_state=review_pending/live/rejected/restricted/removed/unknown；两者分别记录，公开发布完成须 verified 且 live。人工核对不等于官方API证明，凭据级别单独展示。

如果发布时人工改过文案或媒体，须登记差异并创建实际发布版本，重新完成必要审查；不能把旧审批标成仍有效。迟到回执或失效后误发仍需保存历史事实，标为 inconsistent 并进入复核，不能因当前门禁失败拒绝留档。撤回请求生成负责人任务，不把产品内撤回状态当作平台已删除，必须记录平台处理回执。

验收：下载不计入已发布数量；同一个平台账号的同一作品不重复建记录；后台凭据与作品关联可核查；未取得开放权限不出现自动发布按钮。

### FR10 发布效果记录

首轮使用客户后台截图或导出表人工录入。每个 MetricSnapshot 包含 publication_id、观测窗口、指标名称、指标单位、指标定义、累计或增量口径、来源、录入人、采集时间和证明。不可获得的指标为空并标明缺失，不写为零。修改数据保留原值和原因。

主平台建议在发布后 D1、D7、D30 记录累计播放、完播指标、互动及平台可提供的咨询入口数据。并非每个账号提供所有字段，只有来源明确且口径可比较的指标进入对比。小红书单独展示其可得数据，不把两个平台播放量合并成去重触达。

验收：可以追到每项数据凭据；不同窗口和平台口径不能直接排名；系统不把账号粉丝数作为内容曝光或客户数；D30 尚未成熟的作品显示等待观察。

### FR11 合规咨询承接

一个 LeadEntry 的 capability_mode 只能是 manual_native、approved_native_component 或 owned_form_allowed。默认 manual_native，即客户在平台允许路径主动咨询，销售人工回应，在取得相应授权后录入最少必要信息。approved_native_component 需要账号和官方组件实际权限证明；owned_form_allowed 只有具体平台允许外部入口且已核对展示位置时才能启用。

入口要说明服务主体、用途、隐私说明、联系方式的使用范围和取消方式。可联系性不必要求手机号：客户允许通过平台内账号联系也可以。首轮不收集资产证明、身份证、精确家庭成员健康情况或房产资产清单。预约所需其他资料由客户按独立合法流程处理。

公开表单如启用，需空字段校验、授权确认、去重、防滥用和提交回执；未同意不能预勾选或自动提交。客户重复提交不重复计新增资格线索。人工导入必须填写用户主动咨询或授权依据，不从私信截图批量抽取联系人，也不自动把未授权信息发给模型。

验收：未获权限入口不能启用；取消授权后停止相应联系并处理删除；来源未知保留 unknown；不能自动私信或从平台抓取私信内容。

### FR12 轻 CRM 与反馈

数据链为 SourceTouch → InquiryCandidate → QualifiedLead；没有独立触点的人工咨询允许从 InquiryCandidate 开始，不能虚构 SourceTouch。InquiryCandidate 是咨询候选，不要求已经有全部联系方式。销售确认“可联系、真实置业或看房需求、匹配本楼盘或明确后续跟进理由”后才生成资格线索。

之后阶段为 qualified → appointment → visit_completed → opportunity → won 或 lost；withdrawn 用于退出或撤回。预算、时间、区域偏好可以 unknown；没有预算不能自动判无效。所有转换记录实际时间、销售、依据和下一步；预约不代表已带看，带看不代表成交。预约取消是事件，不伪造 visit_completed。

同一 tenant 内按获授权的稳定联系标识提出去重候选，销售确认身份后合并；共享家庭电话不能自动判为同一人，联系匹配键不能成为 Contact 的全局或租户唯一身份约束。同一客户多次咨询关联多个触点，不删除已有历史。来源有 confirmed、self_reported、inferred、unknown 等证据级别；模型相似判断不能成为 confirmed。首触和末触仅限已有证据的触点，交易归因仍应谨慎。

跟进界面展示内容上下文、客户主动提供的需求、最近反馈、负责人及下次跟进时间。销售用结构化原因记录：内容误解、资料不足、不适合的需求、时间不符、预算未匹配、暂时无需求、来源不明或其他。AI 仅接收脱敏需求与反馈，不接收联系方式；提出后续选题、资料修正和话术草稿，必须由运营批准。

验收：只有销售能确认资格；模型分数不改变阶段；跨租户去重和联系人读取失败；反馈建议不会自动改事实、改价格、联系客户或创建对外发布。

## 8 状态机与变更规则

内容主状态建议为 draft、needs_info、in_review、approved、exported、publication_pending、published、blocked、withdrawn。内容版本、发布快照和 Publication 分别保存状态，不能用一个字段替代全部对象。正式实现枚举和合法转换见[API 契约](06_数据模型与API契约.md)。

| 事件 | 用户看到的结果 | 系统处理 |
| --- | --- | --- |
| 事实到期或产生冲突 | 待确认资料，显示受影响内容 | 阻塞新审批；已发布进入复核任务 |
| 素材授权撤回 | 受影响镜头和渠道可见 | 禁止新导出，生成撤回任务，保留最少必要审计 |
| 已批准脚本被编辑 | 新草稿，原审批可回看 | 新版本必须重审 |
| 渲染或模型超时 | 可恢复失败，显示已完成部分 | 按同一任务幂等重试，达到预算上限暂停 |
| 平台审核拒绝 | 发布未完成，显示人工记录原因 | 不计成功发布，保留导出及尝试记录 |
| 入口权限失效 | 暂停入口并通知负责人 | 不自动跳到未经批准的站外路径 |
| 客户撤回联系授权 | 停止相应用途的联系 | 权限撤回、删除流程与审计按实际义务处理 |
| 销售长期未反馈 | 待负责人处理 | 未反馈保持缺失，不推断线索无效 |

## 9 数据对象与追溯要求

核心对象包括 Tenant、Property、Fact、Asset、BrandProfile、Campaign、ContentVersion、Run、Release、Publication、MetricSnapshot、LeadEntry、SourceTouch、InquiryCandidate、Contact、Consent、QualifiedLead、FollowUp 和 ReviewProposal。

必须能从发布作品追到批准版本、媒体、脚本、事实及其来源；从资格线索追到销售确认、联系授权和已知触点；从复盘建议追到观测窗口和匿名销售反馈。编辑历史和审计不能替代用户删除权；删除后的证据只保留依法必要且最少的部分。

手机号等联系信息与 AI 处理内容分开存储和访问。对 AI 的输入使用匿名需求标签、已公开或获许可的事实及最少必要素材；客户私信、联系人、资产信息和内部报价不可默认发送外部模型。组织管理员可配置允许的模型和数据处理范围。

## 10 AI 工作流及人工控制

Agent 在此指有明确输入输出、工具权限和停止条件的任务单元。建议按资料整理、选题、脚本、分镜、包装、风险检查、复盘七类任务组织；媒体渲染使用确定性工具。系统能显示用到哪些事实、缺什么资料和为什么停止，无需对用户展示内部推理过程。

事实检查 Agent 只能识别待核对问题，不能授予 verified。复盘 Agent 只能创建待批准建议，不能改客户资料、报价、权限或 CRM 阶段。处理上传文档时将其中的指令视作资料内容，不能用来修改系统权限、调用外部网址或读取其他客户数据。

模型输出需通过结构校验、事实引用校验、跨房源校验、禁用主张校验、预算校验和人工审核。供应商失败可切换已获客户允许的供应商，但要保留本次选择和输入范围；不允许以自动切换规避客户的数据处理限制。

## 11 非功能需求

| 领域 | 首轮要求与建议验收值 |
| --- | --- |
| 数据隔离 | tenant_id 在业务、文件、队列和缓存均校验；跨租户访问测试全部拒绝 |
| 访问控制 | 销售仅可见授权客户；运营默认看匿名反馈；支持管理员临时访问有审批及审计 |
| 性能 | 常用列表在50条内容及1000条咨询的试点数据下，服务器处理 P95 建议不超过2秒；AI/渲染异步展示状态 |
| 任务恢复 | 模型和渲染均可重试、取消、看失败原因；用户刷新或 worker 重启不丢已确认任务 |
| 成本 | Campaign 和单任务预算上限可配置，费用按真实供应商回执或明确估算口径记录；超限停止而非无穷重试 |
| 文件 | 上传格式、大小和时长在界面明确；建议首轮视频每文件不超过2GB，最大值由实现与客户素材验证后确认 |
| 可观测性 | run_id 关联各步骤、调用耗时、错误和成本；日志不输出手机号、私信原文、密钥或签名下载地址 |
| 备份恢复 | 试点前完成数据库与对象恢复演练；内部目标 RPO 24小时、RTO 8小时，达成后才对外承诺 |
| 可用性 | 首轮是受控试点，明确支持时段和故障联系人；不提前承诺全年 SLA |
| 兼容性 | 桌面 Web 工作台，手机可查看跟进和入口；首轮无需原生 App |
| 可访问性 | 中文可读、错误说明明确、不只靠颜色表达状态；字幕可校正 |

以上数值是项目内部建议门槛，不是行业基准或已取得的性能结果。技术合伙人需在试点前给出测量条件和实际记录。

## 12 指标与业务验收

系统验收与业务试点分开：系统验收证明链路能运行，业务试点证明用户是否愿意持续使用和付费。二者都不能替代房源营销许可与平台权限。

| 指标 | 口径 | 使用方式 |
| --- | --- | --- |
| 合格内容数 | 在窗口内由批准快照导出且通过内容验收的不同内容版本 | 测量团队可用产能，不等于发布 |
| 已发布作品数 | status=verified 且 platform_state=live 的不同 Publication | 核验公开投放到真实渠道的数量；其他状态单列 |
| 主动咨询数 | 去重后的 InquiryCandidate，排除明确垃圾、内部测试 | 保留 unknown 来源及渠道限制 |
| 资格线索数 | 期间首次由销售确认的 tenant 内去重 Contact，记录所关联楼盘与理由 | 北极星；同一人多次询盘只新增一次 |
| 需求确认率 | 同一首咨 D30 队列内已确认 qualified 的去重人数 ÷ 已确认可联系的去重咨询人数 | 未完成反馈单列，不能随意填无效 |
| 全咨询资格比例 | 同一首咨 D30 队列内已确认 qualified 的去重人数 ÷ 全部去重有效咨询人数 | 与需求确认率一起展示，防止漏斗筛选掩盖结果 |
| 实际带看数 | 有销售记录及真实完成依据的 visit_completed | 与预约分开 |
| 单条合格内容人工时间 | 资料准备、选题、事实核验、拍摄、文案分镜、剪辑、审批、包装、发布及指标与咨询录入的人工作业时间 | 共享前置工作按活动分摊；等待和销售跟进独列；与同口径原流程比较 |
| 活动运营 CPL | 同一周期全部约定生产与获客成本 ÷ 当期新增去重资格联系人 | unknown来源也计入但单列，属于运营观察，不声称内容归因 |
| 作品可归因 CPL | 该作品相同窗口的约定归因成本 ÷ 有可核验作品关联证据的去重资格联系人 | 按指标文档A/B证据规则；归因不足或分母为0显示暂无 |
| 事实问题数 | 发布前发现与发布后发现分别记严重度 | 发布后重大错误建议零容忍 |
| 销售反馈完整率 | 到期应反馈的咨询中完成规定反馈的数量 ÷ 到期咨询数量 | 反映闭环是否真正可用 |

建议试点内部目标：同类型内容人工时间比原流程中位数降低30%，发布后重大事实错误为0，已到期咨询反馈完整率达到80%。这些目标须在两周基线后由客户确认；样本少时只报告数量和个案，不对外声称提升百分比。真实业务获客目标由客户按账号、房源和历史数据制定，不预设“保证10条客户”。

详细 D7、D30 观察窗口、事件字段、归因和去重见[指标与 CRM](07_指标归因与CRM闭环.md)。

## 13 内容真实性与平台上线条件

营销主体、房源信息、价格口径、素材授权、广告识别、AI 内容标识、用户联系授权及具体平台入口能力构成上线检查。检查通过的证据要对应账号和渠道。房地产广告不得使用投资回报或价格上涨保证，实际要求按[合规文档](08_内容真实性数据安全与平台规则.md)的官方依据逐项核对。

官方抖音线索能力资料的当前公开检索正文提示私信能力不支持新增准入，因此该能力不能作为首轮必需集成；具体账号的现时权限仍需上线核验。若平台只支持站内人工咨询，产品按该路径记录，不要求用户违规跳转站外表单。[抖音官方线索能力开放说明](https://partner.open-douyin.com/docs/resource/zh-CN/dop/ability/enterprise-account-open-ability/leads-b2c-im-ability/clue-component-open)

规则状态可能变化，负责人须在接入和上线时复核实际官方入口。没有证据的权限显示“待确认”，不能用产品功能按钮暗示已获得许可。

## 14 首轮交付与时间安排

建议六周开发：第一周确认客户、真实素材、事实库和可用咨询路径；第二周完成权限、资料和事实核验；第三周完成选题、脚本与分镜；第四周完成真实成片与包装；第五周完成发布回执、CRM 与指标；第六周完成联调、恢复、权限与内容验收。原流程连续两周基线在研发W1至W2并行记录，或回收可核验历史数据。之后进行四周业务试点；基线缺失时不报告效率提升百分比，必要时补齐并顺延。

开始日期由人员到位和客户资料确认决定。若入口资质或素材不足，应提前降为已批准的人工路径或调整计划，而不是赶工跳过审核。详细任务和验收案例见[研发计划](09_MVP研发计划与验收.md)。

技术交付需包括可运行测试环境、版本化代码与部署说明、真实成片、审批与发布记录、明确标记测试数据的 CRM 流程、使用 SOP、权限检查、成本记录及问题清单。四周业务试点另交付实际咨询与销售反馈复盘；没有真实咨询时报告零结果，不能以测试记录证明获客，也不因没有客源否定已经通过的技术功能验收。技术可运行和用户愿意付费分别出具证据。

## 15 关键风险与处理

| 风险 | 早期信号 | 首轮处理 | 责任人 |
| --- | --- | --- | --- |
| 房源许可或资料不足 | 无证明、报价冲突、未确认产权表述 | 暂停发布，补证据或更换试点楼盘 | 创始人与事实负责人 |
| 高播放低咨询 | 内容偏猎奇，CTA 与真实需求脱节 | 测试需求型选题，保留观看与需求的区别 | 运营与销售 |
| 销售不反馈 | 咨询无负责人或长期未更新 | 明确值班和反馈期限，停止扩大产量 | 销售负责人 |
| 视觉有美感但不真实 | 生成景观、夸大空间、错用房源镜头 | 只用真实素材，逐镜头核验 | 内容审核人 |
| 平台能力不开放 | 未获资质、入口无法展示 | 人工站内承接，记录实际模式 | 渠道负责人 |
| 模型成本或返工过高 | 重试多、脚本无依据、渲染失败 | 限预算，先补资料，审后再渲染 | 技术负责人 |
| 方法无法复制 | 只有创始人能批准，每次都重写 | 把判断做成案例和规则，记录人工介入 | 创始人与产品负责人 |
| 获客链路无法归因 | 手动咨询无作品来源 | unknown 单列，请客户自愿确认来源 | 销售负责人 |

## 16 决策与评审门槛

本 PRD 进入开发前必须确认客户团队、真实楼盘、营销许可、素材范围、首个平台账号、可用咨询路径、承接销售、模型数据处理范围和首轮预算。定价、CRM 对接和增加平台不阻止当前文档评审，但会改变排期与成本。

每项需求保留 FR 编号；验收用例引用对应 FR；接口和数据对象由[技术架构](05_技术架构与Agent工作流.md)和[API 契约](06_数据模型与API契约.md)细化。范围冲突以事实真实性、客户授权、平台可用性和本 PRD 的首轮范围裁定；任何新增能力须登记新增价值、依赖、成本和验收，不能静默加入六周承诺。

创始人负责确认业务目标，技术合伙人负责估时与实现可行性，运营与销售负责真实试点流程。未确认项与访谈问题统一登记在[决策与访谈](12_决策登记与用户访谈.md)。
