# 楼响 HouSignal｜信息架构与页面交互

版本：v0.1  
日期：2026-10-11  
状态：产品与设计评审稿，未代表系统已实现或已通过验收  
目标用户：豪宅销售团队；首个试点只启用一个组织、一个楼盘、一个内容活动和一个线索入口。

本文将 PRD 中的完整链路落到页面、字段和操作。正式实体与枚举以《技术架构与数据契约》为准；交付验收以《MVP 研发计划与验收》为准。

## 1. 设计原则与范围

用户打开楼响，首先应看到“今天这套房要讲什么、还缺什么、客户由谁跟进”。模型、任务队列和提示词版本只出现在必要的诊断界面，不进入销售的日常主流程。

页面要帮助团队表达三类判断：房子有哪些经过核实的价值；这些价值适合什么人、有什么取舍；内容发出后，哪些咨询真正进入销售流程。专业度来自可追溯事实、真实空间和有依据的判断，不来自夸张辞藻或模仿特定创作者的人设。

P0 为桌面 Web 工作台。移动浏览器可查看审批卡片、补充回执、录入和跟进咨询；不承诺独立 App、移动端完整视频编辑器或自动平台运营。视觉建议采用大面积真实房屋画面、清晰排版与克制的强调色，避免把豪宅营销工作台做成工具按钮集合。

**P0 必须走通：**素材与事实入库 → 选题 → 文案与分镜 → 真实素材剪辑及字幕封面 → 人工审核 → 导出可播放成片 → 人工发布回执 → 指标回填 → 合法咨询录入 → 销售资格确认及跟进 → 复盘。

**P0 不包含：**自动抓取平台数据、自动发布、自动私信、未获准导流、虚构房屋空间、声音克隆、自动判断购房资格、替代成熟 CRM 的所有功能。

## 2. 导航与主要页面

| 一级导航 | 页面 | P0 主要任务 | 默认可见角色 |
|---|---|---|---|
| 工作台 | 项目总览、效果分析 | 汇总项目进展、今日待办、内容表现、客户阶段与下一轮建议 | 按权限显示 |
| 楼盘资料 | 楼盘概览、事实簿、素材库 | 将房屋事实与权利证明准备完整 | 内容、事实审核、组织管理 |
| 内容活动 | 活动简报、选题、文案分镜、成片、发布与复盘 | 完成一条内容到销售的活动链路 | 内容、审核、平台运营、分析 |
| 咨询与客户 | 咨询候选、销售线索、客户详情 | 资格确认、分配、预约与跟进 | 销售、销售管理 |
| 组织设置 | 成员权限、入口能力、模型与用量、审计 | 管理授权范围与账单用量 | 组织管理；按子项授权 |

P0 不单独建立十几个工作流页面。活动详情用顺序步骤条，保留回退和重新编辑入口；工作台中的阻塞事项直接跳到对应字段。

**工作台整合约定（2026-10-14）：**工作台作为当前项目的默认首页，页内设「项目总览 / 效果分析」。项目总览展示项目进展、待办与阻塞、效果摘要和简短复盘建议；效果分析承接作品观察窗口、发布回执核验、指标回填与建议采纳。效果复盘不再占用一级导航，原复盘跳转与楼管家引用进入工作台的效果分析视图。切换项目后回到该项目的总览，分析窗口从 D7 开始。

楼管家保留独立对话入口。总览提供基于项目记录的简短判断与追问入口，详细解释、查找依据和临时问题继续在楼管家中完成。

### 2.1 推荐 URL 与页面上下文

| 页面 | 路由示例 | 必须携带的上下文 |
|---|---|---|
| 工作台 | `/workspace` | 当前组织及角色 |
| 楼盘事实簿 | `/properties/:property_id/facts` | 楼盘、事实版本与生效时间 |
| 素材库 | `/properties/:property_id/assets` | 楼盘、授权范围、素材状态 |
| 活动工作台 | `/campaigns/:campaign_id` | 楼盘、受众、渠道、目标、入口 |
| 文案与分镜 | `/campaigns/:campaign_id/content/:content_id` | 当前内容版本、引用事实和素材 |
| 发布审核 | `/releases/:release_id` | 冻结的内容、权利、入口和渠道快照 |
| 发布与数据 | `/campaigns/:campaign_id/publications` | 发布对象与指标观察窗口 |
| 咨询详情 | `/inquiries/:inquiry_id` | 触点、同意记录、资格确认过程 |
| 销售线索详情 | `/leads/:lead_id` | 销售阶段、下一步、证据与权限 |

路由中的对象 ID 不能替代授权校验。服务端依据登录会话和组织关系读取对象；跨组织对象不返回可推断的业务信息。

## 3. 角色与权限交互

| 角色 | 英文标识 | 可以做什么 | 主要限制 |
|---|---|---|---|
| 组织管理员 | `org_admin` | 邀请成员、配置能力、维护资源与审计 | 管理身份不等于房屋事实已核实 |
| 内容编辑 | `content_editor` | 维护活动、生成与编辑文案、制作成片、提交审核 | 不能用模型结果替代事实核验与发布审核 |
| 事实审核人 | `fact_reviewer` | 核验事实、标注争议或失效、记录来源与版本 | 必须留下人工核验动作与依据 |
| 发布审核人 | `release_reviewer` | 审核内容、版权、渠道包装与 CTA，批准冻结版本 | 不能批准已变更、失效或缺权利的版本 |
| 平台运营 | `platform_operator` | 下载已批准包、人工发布、回填发布与指标回执 | 不获得超出授权的客户联系信息 |
| 销售主管 | `sales_manager` | 分配咨询、确认资格、监督跟进、查看漏斗 | 不得把 AI 建议当作资格确认 |
| 销售 | `sales` | 处理已分配客户、录入同意和跟进、确认业务阶段 | 默认不浏览其他成员的完整联系信息 |
| 分析人员 | `analyst` | 查看脱敏指标、来源完整度和活动复盘 | 默认不查看手机号、私信原文或客户身份 |

小团队可以让一人承担多个角色，但事实核验和发布审核必须保留两个独立操作记录。是否要求不同自然人执行，作为试点治理约定明确；系统不能静默自动批准自己的生成结果。

无权限操作不只把按钮置灰：显示“需要发布审核权限”等具体原因，并提供联系组织管理员的说明。客户字段在页面、导出、日志和分析视图采用同样的权限边界。

## 4. 页面 A：工作台

工作台统一承载项目大看板与复盘入口。默认「项目总览」保留关键结论与操作入口，详细表格、回填和人工采纳放在「效果分析」，避免重复维护两份项目指标页面。

### 4.1 主要区域

- **本周活动卡：**楼盘、活动名称、受众、目标、负责人与当前步骤。
- **阻塞卡：**缺少可用实景、价格待核验、授权到期、审批失效、无合法入口等；每项显示负责人和解决入口。
- **待办卡：**待事实核验、待发布审核、待人工发布、待补回执、待资格确认、今日跟进。
- **闭环卡：**已发布内容数、有效指标快照数、咨询候选数、销售确认线索数、预约数和完成带看数。
- **来源完整度：**已知来源与 unknown 分开显示；缺失来源不是零咨询，也不能补造归因。

指标卡显示口径和时间范围。销售资格确认前的咨询只计入“咨询候选”，不能计入“有效销售线索”。初期不做“预计成交额”“AI 客户质量分”等会掩盖证据边界的主指标。

「发布后 D7 / D30」表示每条作品发布后的累计观察窗口，不是项目最近 7 / 30 天。咨询、资格确认、预约和实际带看按当前项目销售记录分别统计，不能直接作为内容归因转化率。未观察的指标保持待观察；已观察为零才显示 0。每条发布存在窗口记录，也不代表该窗口的所有指标均已取得。

### 4.2 空态与阻塞

| 状态 | 页面表现 | 下一步 |
|---|---|---|
| 尚未配置楼盘 | 显示首个楼盘资料清单 | 建立楼盘，指定事实审核人 |
| 有楼盘但无活动 | 显示活动简报入口 | 选择受众和单条内容目标 |
| 无已发布内容 | 展示制作进度，不展示虚拟效果曲线 | 完成成片与审核 |
| 已发布但无指标 | 显示“待回填”，不显示 0 播放 | 上传后台回执并填观察时点 |
| 暂无咨询 | 显示实际运行时长及最近发布状态 | 检查内容和入口，继续观察 |
| 咨询无负责人 | 标为待分配，提醒销售主管 | 分配责任人 |

## 5. 页面 B：楼盘概览与事实簿

### 5.1 楼盘概览字段

| 字段 | 必填与来源 | 交互说明 |
|---|---|---|
| 内部楼盘名称、`property_id` | 必填 | 允许内部名称；对外名称单独核验 |
| 城市、区域、公开展示地址粒度 | 必填 | 按客户授权选择公开粒度，避免暴露私人住址 |
| 物业类型、销售场景 | 必填 | 如新盘、二手住宅；不套用未确认的开发商信息 |
| 项目客户与负责人 | 必填 | 组织内成员选择 |
| 目标客群、主要需求 | 必填 | 写需求与生活场景，避免敏感身份推断 |
| 价格、面积、户型等对外事实 | 按需 | 引用事实簿，不在概览自由覆盖 |
| 允许的承诺与禁用说法 | 必填 | 如不得保值升值承诺、不得混淆面积口径 |
| 销售状态与最近复核时间 | 必填 | 变更触发事实与相关 Release 复核 |

### 5.2 事实簿

一行代表一条可引用事实，而不是整份资料“整体可信”。字段包含 `fact_id`、`revision`、事实类别、原始值、单位与口径、对外表述、来源、来源素材定位、核验状态、核验人、核验时间、有效期、公开范围和争议备注。

| 状态 | UI 标签 | 内容使用规则 |
|---|---|---|
| `unverified` | 待核验 | 可用于内部讨论；不能作为发布版本中的确定事实 |
| `verified` | 已核验 | 在有效期、授权范围和指定口径内可以引用 |
| `disputed` | 有争议 | 阻塞引用该事实的发布审核，显示争议原因 |
| `expired` | 已失效 | 阻塞新审核及受影响的已批准 Release |

价格需标注“总价/单价、币种、适用房源、统计或报价日期”；面积需标注建筑/套内/其他口径；距离或时间需标注测量方式与条件；实景观察需标注拍摄位置和日期。系统提醒不替代核验人的责任。

内容编辑器点选事实标记，可看到证据卡和精确版本。事实修改生成新 revision，不覆盖旧依据；受影响 Release 标记失效并要求重新审核。界面给出受影响内容列表以及仍在平台展示的已发布内容，支持运营记录更正、撤下或确认继续展示的处理结果。

### 5.3 特殊交互

- 核验弹窗要求选择证据、填写核验结论和有效期；无法确定的值可以继续保持待核验。
- 批量上传资料可以生成待核验候选，不允许批量自动设为 verified。
- 租客、屋主、客户个人信息默认不进入可公开事实；涉及私人住址、车牌或证件的素材进入遮挡处理队列。
- 缺失证据显示“补依据”而不是“AI 认证通过”。

## 6. 页面 C：素材库与授权

### 6.1 素材卡字段

`asset_id`、原文件名、素材类型、拍摄/录音日期、楼盘、空间标签、时长/尺寸、拍摄来源、上传人、人物与敏感信息提示、权利证明、`rights_revision`、可用渠道、用途限制、授权期限、许可撤回状态、处理版本与原件关联。

素材类型包括实景照片、实景视频、平面图、项目资料、音频、Logo 与其他附件。实景素材与效果图必须明确标注；效果图不能当作真实已建空间呈现。

P0 允许裁切、曝光与色彩调整、字幕、封面排版、人工选镜头及授权音频组合。不得生成不存在的窗景、扩大房间、删除影响购房判断的结构或把未确认设备替换成更高档设备。AI 装修概念图如后续启用，必须隔离为非实景并单独审批，不进入 P0 默认链路。

### 6.2 上传与预检

上传 → 文件校验 → 音视频元数据读取 → 预览生成 → 权利信息登记 → 可用/需处理/阻塞。

| 情况 | 提示 | 操作 |
|---|---|---|
| 文件损坏或无法解码 | 指明文件和失败原因 | 更换文件；不能继续生成伪成片 |
| 授权证明缺失 | “该素材尚不能进入发布包” | 补证明或替换素材 |
| 授权已到期/撤回 | 阻塞使用并列出受影响版本 | 联系权利负责人处理 |
| 含人物、车牌、屏幕隐私 | 标出疑似区域，等待人工确认 | 遮挡、裁切或删除镜头 |
| 房间素材不完整 | 显示覆盖缺口，如缺主卧实景 | 上传补拍或调整脚本 |
| 同文件重复上传 | 提示组织内已有素材 | 复用或明确建立新版本 |

预检结果是检查建议；不能据此确认版权归属、客户同意或房屋真实性。

## 7. 页面 D：活动简报与选题

活动必填：名称、`campaign_id`、关联楼盘、目标受众、一个核心需求、一个关键取舍、主渠道、负责人、计划发布日期、内容目标、合法入口和试点统计窗口。

首个活动示例：“向重视家庭公共空间、愿意接受该房屋明确取舍的潜在买家，解释餐厨与客厅的真实使用体验，引导感兴趣的人在平台内主动咨询。”示例不包含虚构面积、价格、客户身份或楼盘事实。

选题卡显示：标题、受众问题、核心判断、引用事实、实景支撑、取舍、推荐镜头、CTA、风险提示及建议理由。排序可以给出编辑建议，但不显示未经数据验证的“爆款概率”。

内容编辑可接受、改写或放弃选题。接受只创建草稿，不代表事实已核实。缺少事实或素材的选题标为“补资料后可用”；用户能直接跳到对应资料项。

## 8. 页面 E：文案、分镜与成片

### 8.1 文案分镜编辑器

左侧为结构和正文，中间为分镜，右侧为事实/素材证据。保留一个连续编辑区域，避免用户在多个模型工具间切换。

每个分镜包含：顺序、预计时长、口播/旁白、字幕、镜头意图、关联实景素材、素材起止点、关联事实版本、声音来源、转场与屏幕提示。用户可以调整镜头顺序、裁切区间、字幕和文案。

建议的 60–90 秒结构仅为创作模板：提出真实需求 → 用空间和事实证明价值 → 说明适用人群与取舍 → 给出一个合规咨询动作。不得把该模板当作固定脚本或对小艾大叔内容的逐句复制。

### 8.2 生成与修改操作

- “生成草稿”显示输入摘要、引用事实和本次版本；模型输出落为可编辑草稿。
- “修改这一段”只作用于选中段落；保留前后版本及修改原因。
- “检查依据”标出无事实支持的确定性陈述、口径冲突和来源不明信息。
- “检查素材覆盖”将每段脚本映射到素材，未覆盖段显示“缺素材”。
- “提交审核”冻结当前 `content_version_id`，关联事实 revision、素材权利 revision、渠道包装与入口。
- 审核后修改任一冻结项，创建新版本并重新申请 Release；已批准快照不能就地改写。

### 8.3 成片工作区

预览区显示真实视频、逐句字幕与时间轴；旁边显示使用素材、声音来源和版本。可创建抖音主版和小红书包装版，但两者引用同一事实依据，分别保存标题、封面、正文、标签及 CTA。

P0 默认竖版 1080×1920、60–90 秒为项目建议规格；可播放 MP4、H.264 视频和 AAC 音频作为兼容性建议，最终格式按试点账号当时上传要求人工核对。帧率沿用主素材或统一至常见 25/30 fps，避免混合帧率造成可见卡顿；1080p 视频码率建议初始 8–12 Mbps，依据真实预览和文件大小调整，不当作平台限制。封面、字幕安全区域提供可调模板，避开平台按钮与说明遮挡，不能假定所有终端裁切一致。

字幕必须有人校对人名、楼盘名、数字、面积和价格；字幕与口播不一致时阻塞审核。字幕建议高对比、两行以内优先，具体字号和位置依据手机实看验证。背景音乐只有在权利明确且用途覆盖时使用。首版可采用真人录音或有合法商业使用范围的合成旁白；不使用未经授权的声音模仿。

生成任务展示排队/运行/失败/成功及失败阶段。渲染成功必须提供可播放预览、文件大小、时长、版本和校验标识；没有真实可播放文件就不能显示“成片完成”。重试使用同一任务关联，防止重复计费或产出无法对应版本的文件。

## 9. 页面 F：发布审核与导出

### 9.1 审核包

审核人同时看到成片、脚本、事实证据、素材权利、字幕、渠道文案、封面、CTA 与 `LeadEntry`。审核结论只对应冻结的 Release 快照。

| 检查项 | 阻塞条件 | 处理方式 |
|---|---|---|
| 房屋事实 | 引用待核验、争议、失效或口径冲突事实 | 修订/移除表述并重审 |
| 画面真实 | 实景与效果图混淆，视觉改变影响房屋判断 | 更换镜头或清晰标注 |
| 权利与隐私 | 缺版权、授权过期、个人信息未处理 | 补权利或删除/遮挡 |
| 字幕与音频 | 错误数字、名称、字幕口播冲突 | 人工校对并重渲染 |
| 平台包装 | 包装、标签、CTA 未完成核验 | 由运营调整并重审 |
| 线索入口 | 入口未确认可用、范围变更或无合法承接方式 | 使用已核验入口 |
| 可播放成片 | 缺文件、无法播放、音画不完整 | 补素材或重渲染 |

P0 的默认入口为 `capability_mode=manual_native`：客户主动在平台内咨询，由人员在合法、已告知并取得适当同意后录入 CRM。`approved_native_component` 只有经核验的官方组件可开启；`owned_form_allowed` 只有渠道明确允许并完成审核时可开启。未具备能力的入口显示原因与回到人工站内承接的选项，不能继续生成不可执行 CTA。

### 9.2 审核动作与状态

Release：`pending_review` → `approved` / `rejected`；已批准版本可以因事实、素材权利、入口能力或内容变更进入 `invalidated`、因时限进入 `expired`、由授权人主动撤销进入 `revoked`。

批准、拒绝和撤销必须记录人员、时间、对象版本与原因。导出时再次检查 Release 与依赖仍有效。不可导出的页面明确指出阻塞项，不能提供无标识的旧包作为替代。

已批准包包含可播放 MP4、封面、渠道标题/正文/标签/CTA、人工发布检查清单、事实与权利摘要、版本标识。不向公开发布包夹带客户资料、私信截图或内部核验附件。

## 10. 页面 G：人工发布与指标回填

下载导出包以后，平台运营在平台界面人工发布。楼响的“导出完成”与“已发布”是不同状态，不能联动自动改为已发布。

Publication 字段：`publication_id`、`release_id`、渠道、发布账号、实际发布时间、真实 URL 或 `post_id`、发布回执、`receipt_level`、`status`、`platform_state`、录入人、校验结果及撤下/更正处理记录。

| Publication 状态 | UI 标签 | 含义 |
|---|---|---|
| `recorded` | 已录入，待核对 | 用户录入发布信息，真实性仍待人工核对 |
| `verified` | 发布回执已确认 | 有真实 URL 或帖子 ID，且根据对应凭据级别完成核对 |
| `inconsistent` | 信息不一致 | URL、帖子 ID、账号、内容或回执冲突 |
| `removed` | 已撤下 | 人工确认撤下并附处理依据 |

`receipt_level` 使用 `operator_attested`（运营人工确认，P0 默认）、`official_export`（官方导出凭据）或 `platform_api`（获准接口凭据）。`verified` 表示依据相应凭据级别核对，不等于平台接口自动证实；页面必须同时展示凭据级别，不能把运营截图包装为官方 API 回执。

平台实际状态 `platform_state=review_pending/live/rejected/restricted/removed/unknown` 与回执状态分开显示；仅 `status=verified` 且 `platform_state=live` 才进入公开发布完成统计。审核中、拒绝、限制或状态不明不显示已公开发布。迟到回执及失效后误发仍允许留档，以 inconsistent 标记并提出复核任务。

指标快照字段：关联 Publication、`observation_at`、`metric_window`、平台指标原名及定义、播放/曝光/互动等可用值、来源、`receipt_asset_id`、录入人。无法获得的字段保留 unavailable；没有截图或可核验来源的自报值明确标为未核验。

快照列表按观察时点展示，不能用累计快照相加得到总播放。渠道间“播放”“曝光”等不同口径不直接合并成同一效果数。更正指标创建新记录并保留原记录，复盘提示数据完整性。

## 11. 页面 H：咨询候选、销售线索与客户详情

### 11.1 咨询录入

InquiryCandidate 记录咨询事实，包含 `inquiry_id`、时间、渠道、可确认的来源、`source_confidence`、来源凭据类型及引用、关联入口、关联发布内容（可为空）、联系人、需求摘要、联系同意依据、接收人、责任人和去重提示。

没有精确来源时显示 `unknown`；只能依据客户自述、可核验平台上下文或合法追踪记录补来源。客户主动咨询并不等于同意导入全部对话和长期营销，录入人需记录用途、告知与对应同意依据。默认只录入业务所需摘要，不把整段私信送入模型。

`source_confidence` 统一为 `confirmed`、`self_reported`、`inferred`、`unknown`，分别显示“有依据确认”“客户自述”“推测”“未知”。凭据类型另设字段，例如运营截图、官方导出或允许的接口记录，不把凭据类型混进来源可信度枚举。仅凭活动同期推测不能标为 confirmed；有渠道来源但帖子不明确时，只保留被证据支持的归因粒度。

导入前预览：列名映射、合法来源、同意证据、候选重复、缺失字段。错误行单独列出，成功行可追溯；重试不能重复生成咨询。跨组织不提示其他组织是否存在同一联系人。

### 11.2 资格确认卡

销售逐项确认：可联系的渠道与依据、客户表达的购房需求、与当前楼盘的相关性、下一步行动意愿、负责人与确认时间。预算等字段只记录客户主动提供的信息，允许未知；不能要求客户为了成为线索必须提交敏感身份或财产证明。

只有销售人工确认可联系且需求明确，才建立 QualifiedLead。模型可建议“需补问哪些问题”，不得直接创建合格线索或把未经确认的咨询显示为高质量客户。

### 11.3 销售详情

显示 Contact 脱敏身份、已授权联系渠道、客户自述需求、来源完整度、当前业务阶段、负责人、最近跟进、下一步时间、预约/带看/机会证据及 consent 状态。

业务漏斗展示：询盘候选 → 销售确认合格 → 预约 → 完成带看 → 销售机会 → 成交/失败/退出。正式阶段使用 `qualified`、`appointment`、`visit_completed`、`opportunity`、`won`、`lost`、`withdrawn`。日常联系用 FollowUp 记录，不通过“跟进中”掩盖漏斗阶段。

FollowUp 字段：`occurred_at`、`actor_id`、渠道、脱敏备注、客户明确反馈、下一步、`next_action_at` 和 `evidence_ref`。预约建立在客户确认上；完成带看由销售确认并留证；销售机会代表双方有明确推进事项；成交与失败必须人工录入原因和适当凭证。不得把“销售发出邀请”当作已预约，把“预约存在”当作已完成带看。

### 11.4 退出、撤回与去重

- 客户不再继续销售流程可进入 `withdrawn`，与隐私同意撤回分开记录。
- 同意撤回后阻塞新增营销、提醒和模型处理，按保留与删除规则处理资料；可保留的审计记录脱敏展示。
- 合并重复咨询先展示两个对象和冲突字段，人工选择；保留来源与合并轨迹，不重计 QualifiedLead。
- 提供更正来源的理由与证据；不能把 unknown 批量改成当前活动。
- 客户详情无权限时不给出隐藏手机号长度、是否重复等旁路信息。

## 12. 页面 I：复盘与下一轮简报

复盘以 Campaign 为单位显示三层结果：内容交付及时间成本；平台可验证效果；销售资格和业务推进。页面明确各层数据是否完整，分开显示已知来源、未知来源以及仍未处理的咨询。

复盘编辑器要求填写：原假设、观察窗口、证据、实际发生的结果、可能解释、不能确定的因素、下一轮只改变什么。AI 可以整理建议，内容负责人和销售主管共同确认后，才能写入下一轮简报。

例如“播放下降可能与发布时间或受众不匹配有关”是待验证解释；“该客厅镜头带来 3 位客户”必须有可核验归因，否则展示为“该活动期间新增 3 条来源未明确咨询”。

### 12.1 全局错误与恢复规则

| 错误 | 提示内容 | 恢复与防误操作 |
|---|---|---|
| 网络中断 | 保留草稿并显示最近保存时间 | 重连后同步，版本冲突先比较再选择 |
| 模型失败或超时 | 明确失败步骤、已保存产物及可重试范围 | 原任务重试，不覆盖人工修改 |
| 渲染失败 | 明确素材/解码/资源/参数等阶段 | 修正后重试，已成功任务不重复建单 |
| 事实或权利失效 | 列出受影响版本及处理负责人 | 重核验、修订并重审 |
| 入口能力降级 | CTA 与新发布受阻塞 | 改为已核验人工站内承接并重审 |
| 权限变化 | 停止返回受限数据，说明新的可用操作 | 不保留可继续下载的旧公开链接 |
| 多人同时编辑 | 显示版本冲突和各方改动 | 新建版本或合并，不能静默覆盖 |
| 回执不一致 | 显示账号、链接或时间冲突 | 人工补证；不计入确认发布 |
| 客户撤回 | 禁止后续联系/模型调用并显示处理状态 | 由授权人员执行删除或脱敏流程 |

## 13. 设计交付清单

P0 设计稿必须覆盖上述主页面、移动审批/咨询简版、关键弹窗、空态、错误态、加载态、失效态、无权限态。每个设计节点标注读写对象、角色、事件与是否阻塞发布；同时交付可点击原型和一条从缺资料到完成复盘的演示路径。

设计验收不以画面数量衡量。内容编辑能找到缺失事实，审核人能看到真实依据，运营能确认准确版本，销售能分清咨询和合格线索，分析人员能识别 unknown 来源，才算交互落地。
