# 楼响 HouSignal｜付费试点与商业方案

版本：v0.1  
日期：2026-10-11  
状态：商业与合作讨论稿，价格、预算、阈值均为内部建议假设，不是市场事实或法律条款  
对象：首个豪宅销售团队、创业团队与拟加入的 AI CTO / 技术合伙人。

楼响首期卖的是“能被团队持续使用的房产内容与咨询反馈闭环”。客户购买系统、工作流和明确的交付服务；是否愿意持续付费，要靠真实试点验证。播放、咨询、带看和成交均不作保量承诺。

## 1. 首个客户与付费价值

优先选择有真实房源资料、实景拍摄能力、可运营账号、明确销售跟进人员的豪宅销售团队。首个客户应能共同核验事实、审批发布，并持续反馈咨询和带看结果。

| 客户当前问题 | 楼响提供的价值 | 试点验证方式 |
|---|---|---|
| 专业判断集中在少数人，内容难稳定产出 | 将房屋事实、真实空间和受众取舍转成可复用内容简报与脚本 | 检查审核通过率、返工原因及人员实际使用 |
| 写稿、剪辑、字幕、封面相互割裂 | 一个活动中完成可播放内容与渠道包装 | 测量从资料齐备到批准成片的人时和总历时 |
| 文案夸大、资料过期或权利不清 | 事实和素材版本门禁，人工核验和审核 | 检查违规/失实遗漏和失效处理 |
| 发布后只有播放，客户来源说不清 | 发布回执、指标窗口、合法咨询和 unknown 来源可见 | 检查数据完整度，不制造精确归因 |
| 内容团队不知道客户为何有意向或流失 | 销售资格确认、跟进与复盘反馈 | 看下一轮简报是否使用真实反馈 |

创始人的房产业务经验、内容方法、种子客户与账号影响力可降低验证成本。用户提供的“全网 800W+ 粉丝”是招募背景，本文未独立核验；它不等于产品客户数，也不等于可以自由导出粉丝身份、私信和平台数据。

## 2. 四周付费试点产品

试点在 6 周研发并完成系统交付验收后运行；两周 CTO 试合作属于研发早期，不与客户业务试点混淆。

两周原流程基线建议在研发 W1–W2 由客户并行记录，也可回收有回执、人工时间记录和可核对口径的历史连续两周数据。随后四周试点 P1 用于首批内容与运行确认；没有基线或样本不可比时不得宣称效率/转化提升百分比，需要比较结论的须补齐前提并视情况顺延。

| 项目 | 默认范围 |
|---|---|
| 客户组织 | 1 个客户团队，建议不超过 5–8 名直接参与成员，具体按职责确定 |
| 房源 | 1 个真实楼盘/房源范围，报价和授权边界明确 |
| 目标 | 1 条完整内容到咨询到 CRM 反馈链路 |
| 渠道 | 抖音主渠道；小红书可做包装适配，正式发布另确认 |
| 内容 | 至少 1 条 60–90 秒真实成片走通闭环；每周 1–2 条为排期假设，依资料与人员承载调整 |
| 线索入口 | 1 个合法入口，默认平台内人工承接；正式组件/自有表单仅在已核验可用时启用 |
| CRM | 咨询录入与分配、销售资格确认、跟进、预约/带看/机会/结果 |
| 支持 | 入门培训、每周一次联合复盘、工作时段支持和问题记录 |
| 交付证据 | 发布回执、指标快照、同意依据、销售确认、试点报告及建议 |

不包含现场拍摄、房屋经纪服务、代替销售谈判、保证成交、账号代运营全部工作、平台广告费用、无限生成、未经批准的平台自动化或客户完整 CRM 迁移。任何新增项要写进范围变更单。

## 3. 客户招募与准入

建议邀请 3–5 个种子团队访谈，最终选 1 个深度试点客户。数量是内部行动建议，不是已落实客户资源。访谈重点是当前工作如何发生以及谁愿意投入配合，避免只问“喜欢不喜欢 AI”。

准入条件：

1. 有可公开推广的真实房源，且有人能核实对外事实。
2. 能提供支撑首条内容的合法实景和声音素材，或愿意先补拍。
3. 账号可由客户人员人工发布；客户不要求系统绕过平台规则。
4. 指定内容审核、平台运营和销售跟进人员，承诺及时提供实际反馈。
5. 可在合法告知与同意下录入必要咨询资料，接受来源未知保留 unknown。
6. 接受付费试点、明确范围与无获客保量承诺，愿意评估结束后是否续费。

如果某团队只有“给我几篇爆款文案”的需求，可以提供独立内容服务，但不能把它算作楼响闭环产品已验证。

## 4. 定价与预算假设

### 4.1 试点定价建议

可用“一次性四周试点费 + 约定的使用额度/人工支持范围”作为最初收费方式。建议洽谈区间为人民币 **15,000–30,000 元/团队/四周**，仅是本项目验证用假设；并未调研或引用市场成交价。

以 **18,000 元/四周** 作一个内部示例：客户获得上述默认范围、培训、每周复盘和明确支持时段，额外拍摄/人工制作/广告/扩展功能另列。按可交付节点支付，例如启动、完成首条闭环、提交复盘报告；具体比例、验收与退款处理由双方书面约定。

收费应围绕真实交付，不采用“承诺 N 个高净值客户”或把咨询候选计作合格客户的付费条款。后续是否采取团队订阅、工作流服务费或混合模式，要看试点中的使用、成本和续费证据。

### 4.2 六周研发预算示例

以下是金额计算示例，不是人员市场报价、实际已支付金额或模型官方价格。

| 科目 | 内部假设 | 示例金额（元） |
|---|---|---:|
| CTO / 技术负责人 | 6 周 × 10,000 元/周；可包含早期两周试合作 | 60,000 |
| 全栈工程支持 | 6 周 × 6,000 元/周 | 36,000 |
| 设计、QA、媒体支持 | 按交付范围列支 | 12,000 |
| 模型、渲染、存储等研发使用 | 预算储备，按实测用量调整 | 3,000 |
| 预备费用 | 应对明确问题，支出需有记录 | 9,000 |
| **合计** | **六周示例，不含广告和客户销售人员成本** | **120,000** |

模型/API 费用需在选型当时取得实际报价并实测，不能把预算储备当作确定成本。首周设项目总限额、单次任务限额、异常告警和预算负责人；超额任务不静默扣费。

### 4.3 四周试点运营预算示例

| 科目 | 示例金额（元） | 说明 |
|---|---:|---|
| 内容/运营支持 | 8,000 | 含培训、审核协调与每周复盘；范围明确 |
| 工程支持与修复储备 | 6,000 | 既有范围内问题；新需求另排期 |
| 模型、渲染、存储运行 | 1,500 | 储备假设，实际需逐任务核算 |
| 预备费用 | 2,500 | 经既定预算负责人确认 |
| **合计** | **18,000** | 不含客户自己的销售/拍摄人力和广告费用 |

两阶段示例总预算为 **138,000 元**。18,000 元的单客户试点收入只覆盖示例运营预算，不能证明已回收研发投入或形成利润。创始人和客户人员的投入也应记录，避免用“内部人力免费”制造成本优势。

### 4.4 单位经济记录

必须分别记录模型调用、渲染、存储、人工作稿、事实核验、审批、平台发布、咨询录入与销售跟进。按以下实际口径计算：

- 每条批准成片成本 = 该活动相关直接成本 ÷ 实际批准成片数。
- 每条发布内容成本 = 内容/包装/发布直接成本 ÷ status=verified且platform_state=live的公开发布数，其他状态单列。
- 活动运营 CPL = 同一周期全部约定生产与获客成本 ÷ 当期新增去重资格联系人；unknown来源也计入但单列，属于运营观察。
- 作品可归因 CPL = 该作品相同窗口的约定归因成本 ÷ 有指标文档A/B作品证据的去重资格联系人；归因不足或分母为零不计算，不能把全部同期线索归给作品。
- 内容生产节省 = 同口径人工基线人时 − 实际人时；基线来自研发期间记录或经核验的历史连续两周原流程，不把等待审批和人工作业混为模型速度。基线缺失或不可比则显示待验证。
- 试点毛贡献 = 客户实际收入 − 本期直接交付/运行成本；研发投入与间接成本另外列出。

人工生产总时间统一包含资料准备、选题、事实核验、拍摄、文案分镜、剪辑、审批、包装、发布及指标与咨询录入；共享资料工作按活动分摊，等待和销售跟进独列。另可展示资料齐备后的编辑时间作子指标，不能替代总时间。归因不足时可展示试点期全部成本与全部线索的运营观察，但须说明不是每条内容的确定获客成本，更不能将自报同期增长写成产品因果收益。

## 5. 试点指标与判断门槛

下列门槛是内部讨论建议，应在开始前和客户共同确认基线与数据口径。它们不是市场标准、平台指标保证或合同保量。

| 层次 | 核心指标 | 内部建议判断方式 |
|---|---|---|
| 系统可用 | 成片、审核、发布、咨询、CRM、复盘是否走通 | P0 关键用例全部通过；真实成片与发布回执不可缺 |
| 真实性/治理 | 发布前事实和权利检查、失效处理 | 不接受关键事实/权利/隐私门禁遗漏；有问题先修复 |
| 工作效率 | 资料齐备后的人工净投入、返工 | 先有可核验且可比的两周原流程基线，再积累至少三条同口径试点内容；30% 人时减少可作为探索目标，缺前提不报提升百分比 |
| 团队使用 | 内容/运营/销售实际使用及按时反馈 | 关键角色能独立操作；不是创业团队全程代操作 |
| 数据完整 | 发布、指标、资格确认、来源完整度 | 必要回执和资格依据完整；unknown 单独报告，不追求伪造 100% 归因 |
| 业务阶段 | 真实咨询、QualifiedLead、预约、带看、机会 | 呈现实数与证据；不存在可保证的数量阈值 |
| 付费意愿 | 对继续使用的决策与实际支付 | 书面续费/扩围决定和款项，比口头“很有意思”更有证明力 |

首轮样本很小，效率改善百分比不能包装为普遍性能。若缺基线或没有足够可比内容，结论保持“待验证”；需要比较结论时补齐基线并顺延观察，不能在四周试点第一周才开始基线却按完整四周比较宣传。销售机会只有明确需求、合法可联系、销售确认和下一步业务推进事项，不能只凭模型分数或联系人预算字段成立。

### 5.1 结束决策

| 决策 | 适用条件 | 后续动作 |
|---|---|---|
| 继续单客户迭代 | 系统可用、关键角色在用，客户愿意付费继续；主要问题可修复 | 选择一项最重要改进，再运行同口径试点 |
| 扩至第二客户 | 首客户闭环可由客户人员执行，支持成本可承受，第二客户有配合与付费意愿 | 先复核组织隔离、权限和部署容量再扩围 |
| 收缩产品 | 某一环节有价值，完整闭环使用弱或销售反馈缺失 | 缩减场景，重新定义产品与收费 |
| 暂停业务试点 | 缺真实素材、事实/权利不清、账号或合法入口不可用 | 解决外部前提后重新排期 |
| 结束合作 | 客户需求与产品不匹配、无持续投入或商业价值不足 | 按约定移交、撤销权限和处理数据，形成复盘 |

## 6. 创业团队与客户职责

| 角色 | 必须承担 | 不能转嫁的责任 |
|---|---|---|
| CEO / 创始人 | 定义客户和价值主张、选首客户、落实预算、调配行业/内容资源、最终商业决策 | 不能以粉丝影响力替代客户事实、销售跟进和实际付费 |
| CTO / 技术负责人 | 架构、开发优先级、工程交付、数据边界、运行可靠性与成本；报告未验证事项 | 不能把 Demo 当交付，也不负责凭空承诺获客或成交 |
| 产品/设计负责人 | 访谈、PRD、交互、口径、验收与范围变更 | 不能把所有用户要求无条件塞入 P0 |
| 内容负责人 | 活动简报、观点表达、文案、分镜、字幕、封面及人工校对 | 不能让模型猜价格、面积或楼盘事实 |
| 房产事实审核人 | 核验对外事实、有效期、房源状态和专业判断边界 | 不能仅以 AI 输出或网传信息作为核验结论 |
| 发布/运营负责人 | 账号操作、当时规则核验、人工发布、回执与指标回填、站内承接协调 | 不能擅自启用自动私信或未获准导流 |
| 客户销售主管 | 分配、资格口径、客户同意流程、跟进时效、阶段证据及反馈 | 不能把所有询盘都计入有效线索 |
| 客户销售 | 处理分配咨询、记录客户自述需求、下一步与真实带看/结果 | 不能虚填反馈或因果归因 |

建议每周 45–60 分钟联合复盘：内容负责人带制作与效果证据，销售主管带资格和推进证据，CTO 带问题与成本，CEO 决定下周只推进哪些事项。时长是内部安排建议。

## 7. AI CTO 两周付费试合作

### 7.1 合作目的

用真实场景检验双方能否协作：是否理解房产业务、能否交付真实薄切片、如何处理不完整资料与平台限制、工程与成本是否透明。先确定付费范围和移交标准，再开始；不以“未来合伙”换取免费工作。

两周技术试合作费用可暂以 **20,000–30,000 元** 作为洽谈假设，取决于时间投入与交付范围。它不是市场报价。若继续六周研发，应说明是否抵入研发预算、其他工程人员如何计费；不能重复隐性收费或默认额外成员免费配合。

### 7.2 时间与交付

| 时间 | 工作 | 双方需要提供 | 评审产物 |
|---|---|---|---|
| 第 1–2 天 | 访谈与范围校准 | CEO/客户介绍、一个实际楼盘、已有工作流、预算上限 | 问题定义、资料/能力缺口和 P0 边界 |
| 第 3–5 天 | 原型、数据契约与技术风险验证 | 内容/销售共同看原型；授权实景和事实依据 | 可点击原型、状态契约、渲染/存储/模型薄切片方案 |
| 第 6–8 天 | 做一条真实薄切片 | 核验人和内容人员及时反馈 | 资料→脚本→分镜→真实可播放样片；任务成本与失败记录 |
| 第 9–10 天 | 演示、评审与后续排期 | CEO、CTO、内容、销售共同参加 | 演示材料、代码与文档移交、六周计划修订、合作建议 |

两周样片不要求所有 P0 页面完成，更不等于产品上线。试合作如果缺合法素材，应交付明确缺口与可验证技术产物；不能伪造样片成功，也不能以外部阻塞隐藏已完成与未完成的部分。

### 7.3 评估表

| 维度 | 观察问题 |
|---|---|
| 产品判断 | 能否把“豪宅内容”转成具体用户任务、取舍和可验收链路？ |
| 实际交付 | 是否交付真实可运行代码与可播放文件？是否承认并处理失败？ |
| 工程判断 | 契约、权限、任务重试、运行成本是否清晰？是否避免过度建设？ |
| 内容真实性 | 能否追溯事实和素材，拒绝用模型补造房屋细节？ |
| 平台能力 | 是否根据可用能力设计人工降级，而非承诺未获准自动化？ |
| 协作透明 | 能否说明进度、成本、风险、需要客户配合的事项与范围变化？ |
| 长期投入 | 实际可投入时间、决策职责、团队管理和创业预期是否相容？ |

若只有原型和概念而无实际薄切片证据，不进入长期 CTO 承诺；若结果可用但双方节奏不合适，也可以付费交付后结束。评估技术合伙，不等于否定合理的外包服务模式，两种模式应分别明确。

## 8. 长期 CTO / 技术合伙讨论清单

以下是需要双方书面讨论的问题清单，不是代拟法律合同，也不预设股份/期权比例。

- **职责与决策：**谁负责产品优先级、架构、招聘、预算和发布；技术负责人对哪些决策有权限，业务负责人对哪些事实负责。
- **时间投入与薪酬：**全职/兼职、固定时间、现金薪酬、绩效或奖金、其他项目冲突与最低持续投入。
- **股权或期权：**形式、归属条件、等待期、里程碑、稀释、行权、离职和未归属部分；由双方结合公司状况协商。
- **知识产权：**既有工具与新开发代码、提示词、工作流、设计、数据与账号各自归属；开源许可、第三方模型/素材限制；付款和移交关系。
- **内容与人物权利：**创始人、客户、第三方人物的名称、声音、肖像和内容使用边界；小艾大叔公开内容只作研究启发，不代表本人授权、合作或代言。
- **客户和数据责任：**客户资料由谁管理，谁能访问，模型处理范围、保存期限、撤回、删除、导出与审计。
- **保密与利益冲突：**客户资料、商业计划、账号权限、工程信息的保密范围，竞业/竞争项目限制与合理例外，需专业确认。
- **退出与移交：**交接周期、代码/文档/部署和账号移交、费用结清、未完成工作的认定、访问撤销、客户服务连续性与数据处理。
- **争议与变更：**范围、成本和排期变更如何确认；意见不一致时的决策机制；需要专业法律/财税意见的条款。

任何对外招募都应保持这一路径：“明确范围的付费试合作 → 基于实际成果和相处情况讨论长期角色 → 书面确定长期安排”。不应在试合作前口头许诺模糊股权来替代现金投入。

## 9. 对外试点招募口径

可对外说明：

> 楼响正在与首批豪宅销售团队共同验证一条内容到咨询反馈的 AI 工作流。我们用真实房屋素材和经过核验的资料，辅助选题、文案、分镜、字幕封面与成片，再通过人工审核、发布回执和轻 CRM 把销售反馈带回内容。首期只做一个团队、一个楼盘、一个入口的付费试点。欢迎有真实资料、愿意共同运营和提供销售反馈的团队参与。

不要写“自动全网获客”“精准识别高净值客户”“一个月保证成交”“官方已接通所有平台”或“小艾大叔同款/授权产品”。没有当前证据的资质、合作、用户数与案例均不进入对外宣传。

## 10. 签约与启动前确认表

5. 系统验收与业务价值验证分开；未获客、无法归因与缺客户资源的情况有清晰处理。
