# 楼响 HouSignal｜MVP 研发计划与验收

版本：v0.1  
日期：2026-10-11  
状态：建议计划与验收标准，所有进度、测试与上线结论均待实际执行  
首批范围：一个豪宅销售团队、一个楼盘、一个内容活动、一个合法线索入口、内置轻 CRM。

建议用 **6 周研发 + 随后 4 周付费试点**。研发完成证明系统可用；试点用于验证真实业务价值。两者分别验收，不以“有 Demo”代替真实成片和发布回执，也不以“暂无成交”推翻一个确已可用的系统。

用于效果比较的 **两周原流程基线**须在研发期间并行记录，建议安排在 W1–W2；也可回收有原始回执、时间记录且口径可核对的历史连续两周数据。它不是在四周试点 P1 才开始的新工作。缺基线或样本不可比时不能声称提升百分比；需要比较结论的，补齐基线后再进入相应观察，必要时顺延试点。

## 1. P0 范围与交付边界

| 包含 | 交付要求 |
|---|---|
| 楼盘事实与素材 | 事实逐项核验、版本和有效期；用户授权实景素材与权利范围 |
| 活动与内容 | 活动简报、选题候选、脚本、分镜、字幕、封面、渠道包装 |
| 可播放成片 | 至少一条 60–90 秒真实素材成片，人工校对，导出与版本可追溯 |
| 发布审核 | 冻结事实、内容、权利、渠道、CTA、入口，人工审批，失效重审 |
| 发布与指标 | 人工平台发布，真实 URL 或帖子 ID 与回执；指标手录、窗口和回执 |
| 合法咨询承接 | 默认平台内人工承接；客户主动提供且适当同意后，由人员录入 CRM |
| 轻 CRM | 咨询分配、销售资格确认、跟进、预约、完成带看、机会与结果 |
| 复盘 | 数据完整性、unknown 来源、内容与销售结果分层、下一轮简报 |
| 必要治理 | 组织隔离、角色权限、脱敏、同意撤回、依赖失效、任务重试、审计 |

**暂不纳入：**多组织商业化运营、多楼盘组合经营、跨平台自动抓取/发布/私信、全量 CRM 集成、完整视频编辑器、复杂直播实时处理、声音克隆、虚拟房屋改造和无授权图片采集。架构需有组织隔离边界，但试点只运行一个客户组织。

首个内容链路为抖音主版；小红书仅提供包装适配并单独审核，不把双平台正式发布设为默认验收依赖。入口使用 `capability_mode=manual_native`；官方组件和自有表单模式必须先获得当前能力与规则核验证据才可启用。

## 2. 开工前条件与资源

以下是 6 周建议计划的前提，缺失项须作为阻塞登记并调整里程碑，不能依靠 AI 编造资料赶进度。

| 资源 | 负责人 | 开工前可检查的交付 |
|---|---|---|
| 首个真实客户、楼盘与场景 | CEO / 业务负责人 | 联系人、试点范围、真实需求、客户参与确认 |
| 实景与项目资料 | 客户内容负责人 | 至少能支撑一条内容的合法照片/视频与资料；缺口清单 |
| 事实核验能力 | 客户房产业务人员 | 有权核实价格、面积、房源状态等并记录依据 |
| 发布账号及权限 | 客户运营 | 可人工发布的实际账号；不要求提供账号密码给开发人员 |
| 合法承接方式 | 客户运营 + 合规负责人 | 人工站内承接流程、CRM 录入告知与同意记录方案 |
| 跟进人员 | 客户销售主管 | 咨询分配规则、服务时段、跟进责任人与反馈时间 |
| 原流程基线 | 客户内容/运营/销售负责人 | 研发 W1–W2 并行记录原流程连续两周，或提供可核验历史两周数据；口径、回执与实际人时可检查 |
| 研发资源 | CTO | 至少两名覆盖前后端/媒体任务的稳定工程投入；具体配置评估 |
| 模型与运行预算 | CEO + CTO | 单项限额、审批人与付费账户；有成本记录 |

按小团队估算，可由一名 CTO / 技术负责人、一名全栈工程师，加兼职设计/QA/媒体支持承担；若 CTO 同时负责全部工程而无另一名稳定开发者，应缩减范围或延长交付周期。6 周是排期建议，不是对任何人员配置的固定承诺。

## 3. 六周研发里程碑

| 周 | 目标 | 主要任务 | 本周可评审产物 | 进入下一阶段的门槛 |
|---|---|---|---|---|
| W1 | 定义一条完整链路 | 走访首个客户；确认简报、事实/素材、入口、角色；原型、契约、范围和风险评审；客户并行开始原流程基线记录 | 已确认的 P0 清单、字段契约、可点击原型、样本资料缺口、开发拆分、基线口径与记录模板 | 一个实际楼盘可用；存在合法成片素材及承接路径；无关键口径悬空；基线记录负责人已落实 |
| W2 | 验证最难的薄切片 | 事实与素材导入；一版脚本/分镜；最小真实素材合成；后台任务与失败恢复原型；完成两周原流程基线或核验历史两周数据 | 可播放样片、事实引用链、生成/渲染成本与耗时记录、两周试合作评审、基线数据及可比性结论 | 样片来自授权实景；失败能恢复；预算可接受；技术可行性已有实际证据；基线缺失单独标记且不预设比较结论 |
| W3 | 做好内容工作台 | 编辑器、事实核验、素材权利、版本、角色、审批快照；字幕封面与预览 | 从资料到审核的连续操作演示；发布包预览 | 待核验/争议/失效事实和缺权利素材能被阻塞；更改需重审 |
| W4 | 完成发布与咨询闭环 | 导出、人工发布回执、指标快照、入口登记、人工咨询录入、去重与销售资格确认 | 首条 60–90 秒成片；测试账号/试点账号发布回执；咨询和轻 CRM 流程 | 有真实可播放文件；真实发布记录；人工合法录入与销售确认可追溯 |
| W5 | 做好治理与复盘 | 漏斗阶段、跟进、归因完整度、复盘；组织隔离、脱敏、同意撤回、依赖失效、审计 | 单条活动复盘包；关键失败案例结果；权限与撤回证据 | 关键隔离/权利/事实/撤回/归因问题通过；未通过项有阻塞状态 |
| W6 | 联合验收并交付试点 | 连续端到端演练、问题修复、运营培训、部署与备份恢复、预算限额确认 | 验收报告、已知限制、操作手册、部署/恢复记录、正式试点计划 | P0 关键用例通过；客户签认系统交付范围；阻塞缺陷关闭 |

W4 发布需客户授权且账号可用。若账号、资料或审批未就绪，可以继续开发与内部验证，但“真实发布回执”保持待验证，不能把本地预览冒充发布完成。

## 5. 联合验收样本与证据要求

建立一个验收专用组织以及客户授权的试点组织。验收专用组织用于隔离、错误与撤回用例；对外发布只使用获得明确授权的试点资料和账号。

基础样本包含：

- 一个真实楼盘的活动简报；至少一条可支撑核心判断的已核验事实，并有待核验、争议、失效事实供阻塞验证。
- 能完成一条 60–90 秒内容的授权实景；一条缺权利素材、一条撤回/过期素材及一条无法正常解码文件供错误验证。
- 一套有权使用的真人旁白或合成旁白；无权使用的声音只能进入阻塞样本，不进入公开成片。
- 一条真实 Publication 和一个有观察窗口、来源与回执的指标快照。
- 经同意的真实咨询若实际出现，按合法流程录入；系统用例可使用明确标识的测试咨询，测试咨询不能计入试点获客结果。
- 两个组织、多个角色、重复咨询、unknown 来源、撤回同意和关闭结果等测试对象。

每个用例记录：案例 ID、版本/提交标识、环境、执行人、时间、前置条件、步骤、实际结果、通过/失败/阻塞、截图/日志/文件/回执链接、缺陷号。不得预填“通过”。生产客户信息在验收材料中脱敏。

## 6. P0 验收用例

| ID | 场景与步骤摘要 | 预期结果 | 必须保留的证据 |
|---|---|---|---|
| E2E-01 | 从授权楼盘资料开始，创建活动、核验事实、生成脚本与分镜、编辑字幕封面、制作 60–90 秒成片、审核导出 | 连续流程可用；成片来自真实素材；每条事实可定位证据；不存在未批准依赖 | 活动/版本/Release ID、可播放文件、素材映射和人工审核记录 |
| E2E-02 | 用已批准包人工发布，录真实 URL/ID 并核对回执 | 导出不自动计发布；账号、版本与回执一致，status=verified且platform_state=live才计公开发布完成 | Publication、真实 URL/ID、人工发布回执及平台实际状态 |
| E2E-03 | 手录发布指标及回执，录入合法咨询，销售确认后推进预约、带看和机会，再完成复盘 | 指标有窗口；咨询与合格线索分开；每个业务跃迁有销售动作；复盘显示数据边界 | 指标快照、同意依据、资格/跟进记录、复盘包；测试/真实样本标签 |
| FACT-01 | 草稿引用 unverified 或 disputed 事实，提交审核 | 无依据确定性表述被阻塞，提示具体事实和处理入口 | 阻塞画面与事实状态 |
| FACT-02 | 已批准内容的引用事实到期或被改为 disputed | Release 失效；新导出/新发布被阻塞；已发布对象进入处理列表 | 状态、关联对象、通知与处理任务 |
| VER-01 | 审批后修改脚本、素材、字幕、渠道正文、CTA 或入口任一冻结项 | 原审批不覆盖修改；生成新版本并重审 | 新旧版本与审批引用差异 |
| VER-02 | 两位编辑同时修改同一版本 | 不静默覆盖；能比较并建立明确后继版本 | 冲突展示与版本历史 |
| MEDIA-01 | 未上传足够实景，只提供脚本后请求成片 | 显示缺素材及缺口；没有伪造房屋、空文件或虚假完成状态 | 缺口画面与任务结果 |
| MEDIA-02 | 导出已批准成片，手机和桌面实际播放 | 60–90 秒可播放；无断音/黑屏；数字与名称字幕经人工校对；格式及遮挡符合当时账号要求 | 文件、时长/尺寸信息、播放记录、人工校对清单 |
| RIGHT-01 | 使用缺权利或已到期素材提交审核 | 审批/导出受阻塞，能定位权利依赖 | 素材权利与阻塞记录 |
| RIGHT-02 | 批准后撤回某素材授权 | 相关 Release 失效；新导出受阻塞；已发布内容需要人工处理并记录 | 依赖失效、发布处理与人员动作 |
| AUTH-01 | 未授权角色通过页面和直接对象 ID 访问完整客户信息或审批功能 | 服务端拒绝；页面、接口、下载与日志均无越权信息 | 多角色结果、响应及脱敏日志 |
| AUTH-02 | 组织 A 请求组织 B 的事实、素材、咨询、文件和任务 | 无跨组织读取或操作；不泄露对象存在及联系人重复情况 | 直接接口与文件访问结果 |
| AUTH-03 | 成员权限被收回后重复访问旧链接 | 当前权限重新检查，受限文件不能凭旧页面继续下载 | 权限更改与后续访问结果 |
| RUN-01 | 模型调用超时、渲染失败后重试 | 原草稿保存；失败阶段可见；任务幂等且费用/文件可关联；不覆盖人工编辑 | run_id、尝试记录、成本与文件关联 |
| RUN-02 | 用户重复点击生成/导出，网络重试同一请求 | 不重复建同一逻辑任务，不产生重复计数与不明账单 | 请求标识与任务数/费用记录 |
| PUB-01 | 仅有导出文件、尚无真实发布回执 | 保持待发布/未核实，不计入已确认发布 | 页面与统计口径 |
| PUB-02 | URL/ID、账号、内容或回执不一致，随后补正确依据 | 先标 inconsistent；补证与人工复核后才确认，不丢旧记录 | 原/更正回执与审核动作 |
| PUB-03 | 已有核对回执，但平台仍审核中、拒绝、限制或状态未知；另补录失效后误发 | 回执状态与platform_state独立；仅verified+live计公开发布；历史误发可留档inconsistent并处理，不能拒存或掩盖 | 状态显示、统计排除与历史记录 |
| CAP-01 | 不具备官方组件或自有表单能力 | 保留 manual_native 可执行链路；不存在自动私信或未获准外链依赖 | 入口配置、CTA 与人工承接说明 |
| CAP-02 | 已批准入口能力被撤销或规则核验过期 | 相关批准版本失效；更换合法入口和 CTA 后重审 | 能力凭证、失效状态及新审核 |
| METRIC-01 | 两次录入累计播放快照，另有 unavailable 字段 | 不将累计快照相加；缺失字段不作为 0；显示观察窗口 | 快照及复盘结果 |
| METRIC-02 | 指标更正或回执缺失 | 更正保留轨迹；无依据值标未核验；不作为确认结论 | 历史与数据完整性提示 |
| CRM-01 | 来源未知咨询进入系统，模型判断“高意向” | 来源保留 unknown；模型不自动变合格线索；销售确认可联系及需求后才创建 Lead | 候选与销售确认记录 |
| CRM-02 | 同一个合法联系人多次咨询，重复导入/重试后人工合并 | Tenant 内去重；保留多触点；合格线索不重计；错误行可重试 | 导入批次、合并记录、统计 |
| CRM-03 | 客户未确认预约；销售发出邀请后试图计入预约/完成带看 | 不误计；预约须客户确认；完成带看须销售确认与证据 | 阶段变更与证据要求 |
| CRM-04 | 销售录入机会、成交、失败或退出 | 记录操作人、时间、原因及适当依据；无 AI 自动成交 | 阶段轨迹与凭证 |
| CONSENT-01 | 客户撤回联系/模型处理同意 | 后续联系提醒和相关模型处理受阻塞；按约定删除/脱敏，处理有记录 | 同意版本、阻塞与处理结果 |
| ATTR-01 | 人工补来源，只有活动同期而无帖子级证据 | 可以记录活动同期观察，不能伪装精确帖子归因；unknown 仍可见 | 来源依据与复盘表述 |
| ATTR-02 | 同一联系人多次触点及不同内容 | 触点不等于独立线索；口径可解释；不重复计算人头或宣称唯一因果 | 触点/联系人/线索计数对照 |
| OPS-01 | 运行预算触达内部上限，或模型服务不可用 | 提醒并限制新耗费任务；已有草稿可继续人工编辑；不擅自换成未知付费服务 | 限额、告警和恢复结果 |
| OPS-02 | 恢复一次备份到隔离环境 | 核验事实、审批、发布与 CRM 关联可读取；敏感数据仍有权限边界 | 恢复记录及对象一致性检查 |

## 7. 两类验收结论

### 7.1 系统交付验收

系统验收要求所有 P0 关键用例通过，且 E2E-01 与 E2E-02 有真实成片、审核和发布回执。E2E-03 可先用明确标签的测试咨询验证系统链路；是否出现真实合格线索另由业务试点评估。

以下情况不能判为系统验收通过：没有可播放成片；关键引用未经核验；未经授权素材可被导出；任一组织/客户数据越权；审批失效后仍可作为当前版本下载；无发布回执却显示已发布；撤回客户继续进入营销或模型处理；unknown 被伪造精确归因。

### 7.2 业务试点验证

在真实客户运行中观察内容生产效率、专业度与真实性、人员使用、合法咨询、销售确认线索及后续推进。系统验收不能保证获客数量、成交数或投资回报。4 周试点的观察不自动代表长期因果效果；豪宅销售周期较长，预约和带看可作为阶段证据，不能提前折算成收入。

对比使用研发期间收集或核验的连续两周原流程基线，核对房源、素材准备、账号、投放、时间窗口和人工成本口径。若没有基线或可比样本，可继续报告系统运行和真实业务阶段，但效率/转化提升百分比保持“待验证”；需要该结论时补齐前提并顺延观察，不补造历史数据。

若系统已可用而试点没有合格线索，结论应是“系统闭环通过，业务价值未验证/需调整”，并分析内容、账号受众、入口、楼盘匹配和销售执行等因素。若真实业务已有线索但归因缺证据，不能据此宣称某条内容带来客户。

## 8. 随后四周试点

| 周 | 业务动作 | 检查重点 | 输出 |
|---|---|---|---|
| P1 | 销售、内容与运营培训；跑完首批内容；确认实际运行 | 资料准备是否耗时，流程能否被客户团队执行，入口是否实际可用；核对已收集基线的可比性 | 首批发布与运营问题、基线可比性说明；不在此周才开始两周基线 |
| P2 | 依据真实反馈继续产出；每天处理实际咨询 | 审核返工、实际人时、人工承接和同意、资格确认 | 内容/CRM 周报与缺口 |
| P3 | 一次有边界的选题或镜头优化 | 对比窗口与样本是否可比；不要同时改变全部变量 | 变更记录与证据 |
| P4 | 完成复盘，决定继续/收缩/结束 | 系统可用性、商业付费意愿、真实业务阶段与单位成本 | 试点报告、续费或停止决定 |

发布数量由素材和团队承载决定。每周 1–2 条可作为内部排期假设，不写成合同保量或获客保证；若修改频繁、资料核验耗时或账号不可用，按实际情况调整。

## 9. 缺陷、范围变更与停止条件

| 等级 | 例子 | 发布/验收影响 |
|---|---|---|
| 阻塞 | 越权、虚假已发布、事实/权利门禁失效、撤回后继续联系 | 停止受影响上线与试点；修复后重跑相关用例 |
| 高 | 成片无法稳定播放、任务重复耗费、CRM 资格口径错计 | 不签认对应 P0；修复并验证 |
| 中 | 操作费时、错误提示不清、部分非关键兼容问题 | 有回避方式和明确期限后可评审是否进入试点 |
| 低 | 文案、间距和非关键显示问题 | 列入后续修复，不夸大为业务阻塞 |

范围变更单包含：提出人、业务原因、受影响页面/契约/权限/用例、新增工作量区间、预算与日期影响、替代方案、批准人和生效版本。新增自动发布、跨平台自动获客、直播实时工作流、多楼盘、多组织商业化等，应作为后续阶段，不在 6 周内默认为“顺手增加”。

若首个客户无法提供合法实景/事实依据、账号无法发布、承接方式不可用，继续开发能独立验证的能力并冻结相关对外里程碑。若预计成本超过约定上限，先给出实际用量与降范围方案，由既定预算负责人决定后续投入。

## 10. 最终交付物与签认

研发交付：

1. 已确认 PRD、信息架构、字段与状态契约，以及变更记录。
2. 项目代码、部署说明、运行配置清单、账号与权限移交清单；密钥不写入文档和源码。
3. 一条真实可播放成片及审核/发布回执、导出版本与素材/事实依据索引。
4. 轻 CRM 与复盘演示记录，明确区分测试对象和真实业务对象。
5. 验收案例结果、缺陷关闭记录、已知限制与待验证项。
6. 客户运营手册、权限与同意处理流程、故障恢复和成本记录方法。
7. 4 周试点计划、负责人、反馈机制与预算限额。

签认采用明确状态：“通过”“有条件通过（列出非关键限制）”“阻塞”“待外部资源验证”。客户业务负责人确认场景与可用性；内容/事实负责人确认真实性；销售负责人确认 CRM 口径；CTO 确认实现与运行证据。任何人不得把计划表或本文件本身作为实际完成的证明。
