# 楼响 HouSignal 前端交互 Demo

这是一套基于楼响 PRD 的本地 HTML 交互演示，面向豪宅销售团队。设计采用浅色工作台、石墨文字和冷蓝强调色，以真实工作任务组织内容；示例楼盘、客户、资料、指标与审批均为虚构演示数据。

当前版本 v0.4.0 将效果复盘整合进“工作台”，提供“项目总览 / 效果分析”两个视图，侧栏不再单列效果复盘。“楼管家”仍放在 WORKSPACE 标题上方，作为独立入口，打开后可直接开始项目对话。侧栏保持“楼响 Logo → 当前项目 → 功能导航”，已移除顶部团队下拉。团队名称和角色责任集中在“组织设置”，保留团队数据关联。左侧“当前项目”或顶部项目名称可进入切换列表，提供切换项目、新建项目、项目资料完整度三个入口。

## 项目工作台

新打开演示时默认进入工作台的“项目总览”，集中展示项目资料、内容进展、销售指标、今日待办、D7 效果摘要与简短复盘建议。效果摘要只汇总当前项目同一 D7 窗口中已人工核验且公开的作品，区分已测得的零播放、指标待回填与尚待观察；多平台播放按各自口径累计，跨平台合计不去重观看人数；示例数据持续标注为演示指标。复盘建议提供“查看全部建议”和“问问楼管家”入口。

“效果分析”保留原效果复盘的 D7 / D30 独立观察窗口、按平台分组的作品表现、销售阶段、发布回执核对及建议采纳。总览中的效果入口、内容工作室的复盘入口、通知、搜索与楼管家来源链接统一进入“工作台 → 效果分析”；旧的 `navigate('reports')` 调用继续兼容。D7 摘要的效果分析链接始终打开 D7，常规页签切换保留用户已选窗口。切换项目后回到新项目总览并重置为 D7，所有记录与操作继续按项目隔离。

## 楼管家

通过对话读取当前项目的本地记录。支持项目完整汇总、资料缺口、优先跟进客户、指定客户与继续追问、事实与报价查询、内容表现和下一步安排。回答提供原记录入口，可打开事实簿、客户详情、发布回执与项目资料清单。

示例提问：

- “完整汇总当前项目情况，缺什么、关键客户是谁？”
- “现在还缺哪些资料？”
- “谁需要优先跟进？说明理由。”
- “许先生目前什么情况？” → “他的下一步是什么？”
- “最近内容表现如何？”

每次回答重新读取该项目当时的数据，已显示的回答保留提问时的结果；资料或销售状态改变后，可重新提问或选择“重新汇总”。客户优先级依据已记录的业务阶段与下一步，停止联系、已结束、已成交或缺联系授权的客户不进入主动跟进队列。不推算购房概率、客户财力或未确认的内容归因。

对话与草稿按项目分别保存，切换后不会混入其他楼盘记录。查询期间切换项目，结果仍归属发起项目。Enter 发送，Shift + Enter 换行，兼容中文输入法；可使用快捷提问或重新汇总。每项目保留最近 20 轮演示对话，刷新中断的查询会提示重新提问。

此版本为**本地检索交互演示**：查询当前浏览器中的项目记录，由规则组织答复；没有接入大模型、SQL 数据库或后端 Agent 服务，不支持任意问题或通过对话修改业务记录。界面标注“本地数据演示”。

## 项目切换与资料准备

内置云境·壹号和栖岸·观澜两个独立示例。新建项目只保存用户填写的信息，事实保持待核验，素材、文案、发布与客户记录从空白开始；切回已有项目会恢复该项目的内容和记录。旧版单项目浏览器数据可迁入云境项目，保留原有编辑。新版本使用独立的本地存储键，项目集合和当前选择均可随浏览器保存。

资料完整度按七项清单计算：项目基础资料、营销范围、核心事实核验、项目素材、素材用途、内容目标与渠道、销售承接。每项提供“查看”或“去完善”入口。模板照片和 AI 空间示意不计入真实项目素材准备；完成度不代表真实性认证或平台权限已经取得。

事实簿可补充值、单位和证据位置，先保存为待核验，再人工确认。新项目缺事实或素材时不能生成可批准的内容；项目改名保留旧稿，但需要重新生成或完整修改名称后再审核。延迟完成的演示任务保留发起项目归属，不会写入切换后的项目。

每个项目独立保存事实、素材索引、文案、审批、发布、咨询与销售跟进。团队成员和表达方法仍在同一工作区。用户本地选择的图片仍只在当前页面会话预览，刷新后需重新选择；受影响的预览与审批会失效。

## 打开方式

直接双击 [单文件交互 Demo](dist/楼响_HouSignal_交互Demo.html)，使用 Chrome、Safari 或 Edge 打开。HTML 内含全部样式、脚本和四张图片，无需安装依赖、登录或连接服务器。演示改动可保存在当前浏览器；“组织设置 → 恢复初始演示”可重置。不同浏览器对本地文件存储策略不同，禁止存储时仍能在当前页面操作。

如需开发，使用 dist/index.html、styles.css、model.js、ui.js、views.js 和 assets。可在 dist 目录运行 Python 静态 HTTP 服务；所有交互仍在浏览器本地完成。重新生成独立 HTML 使用 Python 运行 build_standalone.py，无第三方依赖。

项目工作区与隔离逻辑位于 dist/project-store.js，脚本加载顺序为 model.js → project-store.js → ui.js → views.js → assistant-model.js → assistant-session.js → assistant-view.js → app.js。助手查询、对话状态和界面样式分别位于 assistant-model.js、assistant-session.js、assistant-view.js、assistant.css。

## 七个主入口

| 页面 | 可演示操作 |
| --- | --- |
| 楼管家 | 项目对话、汇总与缺项、关键客户与追问、来源跳转、按项目保存对话 |
| 工作台 | 项目总览展示项目进展、待办、效果摘要与复盘建议；效果分析承接 D7/D30、回执核对和建议采纳 |
| 内容工作室 | 六步链路：选题 → 文案 → 分镜预览 → 人工审核 → 导出和回执 → 复盘 |
| 楼盘资料 | 查看来源、筛选核验状态、重新核验完整资料、标记失效并阻塞旧审批 |
| 素材库 | 筛选模板照片、查看用途、本地选择图片并确认演示用途；变更后重审 |
| 咨询与客户 | 录入咨询、四项人工需求确认、搜索与看板、客户详情、跟进、预约和退出 |
| 组织设置 | 切换演示角色、查看咨询承接路径、了解权限边界及重置 |

## 推荐演示路径

1. 工作台选择“开始创作”，选一个具体的生活问题并生成示例文案。
2. 编辑草稿、查看事实依据，进入视觉制作；修改比例、字幕和封面，生成照片序列的分镜预览。
3. 在发布审核逐项查看内容并勾选人工确认，批准当前示例版本；修改任一依赖后旧批准失效。
4. 导出示例文案和 JSON 清单，人工登记示例作品链接。回执核对与平台状态分开记录，只有 verified + live 计公开发布。
5. 进入咨询与客户，先尝试不勾选确认而建立线索，再完成四项人工确认，观察来源未知仍保持未知。
6. 在客户详情保存沟通反馈、逐步记录预约与真实完成阶段；在“工作台 → 效果分析”中采纳下一条内容建议。

生成文案为本地预设样例的组装；媒体预览为照片序列，不生成 MP4。导出包仅包含示例文案、分镜与审核清单。页面没有接入真实模型、平台账号、公开发布、私信或正式 CRM。用户选择的图片只在当前浏览器内预览，不上传外部服务；刷新后需要重新选择本地图片并重新预览/审核。

## 验证范围

行为测试覆盖工作台页签与旧入口兼容、D7/D30、缺失指标、回执与建议操作、项目切换隔离，以及版本失效、事实与权利门禁、包装与媒体设置、销售资格、阶段和撤回。使用 Node 的内置测试运行器执行：

```sh
node --test tests/*.test.cjs
```

浏览器验证另外记录选题、编辑、分镜预览、审核、导出、回执、咨询确认、跟进、筛选及手机布局。静态截图位于 screenshots。测试和截图只证明本地演示行为，不证明产品已经上线、获得平台权限或产生真实客户。
